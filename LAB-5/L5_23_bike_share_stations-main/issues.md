# Lab 5: Static Code Analysis — Identified Issues

The following issues were identified using **Bandit**, **Pylint**, and **Flake8** on `bike_share_stations.py`. High and medium severity security issues are listed first, followed by logic bugs, code smells, and style violations.

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| **SQL Injection (B608)** | Security (Medium) | 9 | `INSERT INTO` query is constructed using string concatenation with variable `name`, `capacity`, and `bikes`, creating an SQL injection vulnerability where untrusted input can execute arbitrary SQL commands. | Replace raw string concatenation with a parameterized query using SQLite placeholders `(?, ?, ?)` and pass parameters as a tuple. |
| **Insecure Pseudo-Random Generator (B311)** | Security (Low) | 22 | Function `unlockPin` uses `random.randint(1000, 9999)` to generate unlock PINs. The standard `random` module is pseudo-random and predictable, making it unsuitable for security/cryptographic credentials. | Replace `random` with the cryptographically secure `secrets` module (`secrets.randbelow(9000) + 1000`). |
| **Silent Exception Suppression / Broad Catch (B110 / W0718)** | Security / Code Quality | 34–35 | `resetStation` uses `try ... except Exception: pass`. Catching the general `Exception` class and silently passing swallows unexpected operational errors, database corruption, or syntax errors without logging. | Catch specific database errors (`sqlite3.Error`) and log or print an error message instead of silently ignoring the failure. |
| **Dangerous Mutable Default Argument (W0102)** | Bug / Logic | 8 | Function `addStation` defines `log=[]` as a default parameter. In Python, default mutable objects are created once at definition time and shared across subsequent function calls, causing unwanted state leakage. | Set the default parameter to `log=None` and initialize `log = []` inside the function body if `log is None`. |
| **Inconsistent Return Statements (R1710)** | Quality / Logic | 14–19 | Function `rentBike` returns `True` if a bike is successfully rented, but implicitly falls off the end returning `None` otherwise. Inconsistent returns make control flow ambiguous. | Make return paths explicit: explicitly return `True` on success and `None` when the station has no bikes or does not exist. |
| **Unused Variable (W0612 / F841)** | Dead Code | 27 | Variable `summary` is assigned the value of `len(stations)` but is never referenced or used anywhere in `fullStations`. | Remove the redundant variable assignment `summary = len(stations)`. |
| **Unsafe `None` Comparison & Potential Subscript Error (C0121 / E711)** | Bug / Style | 39–40 | Line 40 checks `if row[0] == None`. Testing identity against `None` should use `is None`. Furthermore, if `station_id` does not exist in the database, `row` is `None`, causing `row[0]` to raise an unhandled `TypeError`. | Safely check `if row is None or row[0] is None: return False` using identity comparison `is None`. |
| **Non-Standard Function Naming (C0103)** | Style (PEP 8) | 8, 14, 21, 25, 31, 38 | Functions (`addStation`, `rentBike`, `unlockPin`, `fullStations`, `resetStation`, `hasBikes`) use `camelCase` naming conventions instead of PEP 8 standard `snake_case`. | Refactor function names to `snake_case` (`add_station`, `rent_bike`, etc.) and provide backwards-compatible aliases if necessary. |
| **Missing Module & Function Docstrings (C0114 / C0116)** | Documentation | 1, 8, 14, 21, 25, 31, 38, 45 | The module and its public functions lack docstrings explaining their purpose, parameters, and return values. | Add descriptive docstrings at the top of the module and inside each function. |
| **Line Length & Trailing Whitespace (E501 / W291 / C0301)** | Style (PEP 8) | 5, 9, 15, 17, 26, 27, 33, 39 | Multiple lines exceed 79 characters (e.g., Line 9 is 131 characters), and Line 27 contains trailing spaces. | Wrap SQL statements across multiple lines to stay under 79 characters, and remove trailing whitespace. |
